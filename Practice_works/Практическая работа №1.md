**2.7**

Headers:

Content-Type показывает, в каком формате пришли данные. Обычно это application/json, значит сервер вернул данные в формате JSON.

Cache-Control говорит браузеру, можно ли сохранять ответ и на сколько. no-cache означает, что каждый раз нужно проверять, не изменились ли данные на сервере.

ETag уникальный идентификатор версии ответа. Если данные на сервере не менялись, ETag остаётся тем же, и браузер может не загружать их заново, а взять из кэша.

Date дата и время, когда сервер отправил ответ. Помогает понять, когда данные были получены.

Server информация о том, какой сервер обработал запрос, полезно для диагностики, но пользователю обычно не важно.

**2.10**

Сравнение DevTools и Postman

DevTools встроенный инструмент браузера, который показывает, что реально происходит на странице. Он автоматически перехватывает все запросы, которые отправляет сайт, когда человек нажимает на кнопки, открывает страницы, взаимодействует с интерфейсом, можно увидеть каждый запрос, его метод, URL, заголовки, тело ответа, код статуса и время выполнения. Доступны вкладки для анализа производительности, памяти и безопасности. DevTools полезен, когда нужно проверить, почему страница загружается медленно, какие запросы отправляются при нажатии на кнопку, правильно ли работают кэширование и заголовки, когда нужно найти ошибку в работе сайта.

Postman подходит для ручной работы с API, можно самостоятельно создавать любые запросы, указывать метод, URL, заголовки и тело, а затем отправлять их на сервер и сразу видеть ответ. Запросы можно сохранять в коллекции, группировать по проектам, добавлять описания. В нем можно писать автотесты, проверять, правильно ли API обрабатывает разные данные, работать с авторизацией и токенами. Postman подходит для разработки API, когда нужно проверить, как сервер реагирует на разные данные, или отправить нестандартный запрос, лучше для автоматического тестирования.

|   |   |   |
|---|---|---|
||DevTools|Postman|
|Как попадают запросы|Автоматически перехватываются при работе с сайтом|Создаются вручную пользователем|
|Для чего нужен|Анализ сетевой активности живого сайта, проверка кэширования|Ручное тестирование API, разработка, автотесты, документирование|
|Можно ли сохранять запросы|Нет, они видны только в текущей сессии|Да, в коллекциях и папках|
|Поддерживает авторизацию|Да, но только в контексте страницы|Да|
|Можно ли писать тесты|Нет|Да, есть встроенные тесты и скрипты|
|Удобен для|Быстрой отладки и проверки сайта|Глубокого тестирования и разработки API|

Контрольные вопросы

1. Что такое DevTools и какие задачи решают вкладки Elements, Console и Network?

DevTools - встроенные в браузер инструменты для разработчиков.

Elements показывает HTML-код страницы и CSS-стили.

Console выводит ошибки, предупреждения и логи. Также здесь можно выполнять JavaScript-код прямо на странице.

Network показывает все запросы, которые браузер отправляет на сервер. Можно увидеть метод, URL, заголовки, код ответа, размер данных и время загрузки.

2. Как открыть DevTools и какие настройки вкладки Network важны для замеров производительности?

DevTools открывается клавишей F12 или через меню браузера.

Network важные настройки:

Disable cache отключает кэш, чтобы видеть реальную загрузку без сохранённых копий.

Throttling можно выбрать профиль скорости и посмотреть, как страница загружается при медленном интернете.

Clear очистить список перед загрузкой страницы, чтобы не мешали старые запросы.

3. Перечислите основные части HTTP-запроса (метод, URL/параметры, заголовки, тело) и их назначение.

Метод показывает, что нужно сделать с данными (получить, создать, обновить или удалить).

URL и параметры - адрес ресурса на сервере и дополнительные данные в строке запроса.

Заголовки - служебная информация о запросе: формат данных, авторизация, настройки кэша и т.д.

Тело запроса - сами данные, которые отправляются на сервер.

4. Чем отличаются методы GET, POST, PUT, PATCH и DELETE? Приведите по одному практическому примеру.

GET - получить данные (открыть страницу со списком товаров).

POST - создать новый ресурс (зарегистрировать нового пользователя)

PUT - полностью обновить ресурс (полностью заменить профиль пользователя новыми данными).

PATCH - частично обновить ресурс (поменять только аватарку или телефон).

DELETE - удалить ресурс (удалить товар из корзины).

5. Для чего используются методы HEAD и OPTIONS и где встречается preflight-запрос?

HEAD - получает только заголовки ответа без тела. Используется, чтобы проверить, существует ли файл, какой у него размер и т.д.

OPTIONS - спрашивает сервер, какие методы и заголовки разрешены для данного ресурса.

Preflight-запрос - это запрос методом OPTIONS, который браузер автоматически отправляет перед сложными запросами (например, с нестандартными заголовками или с типом данных JSON). Проверяет, разрешит ли сервер такой запрос.

6. Расскажите о группах кодов ответов (1xx–5xx) и приведите примеры для 200, 301/302, 304, 404, 500.

1xx - информационные. 100 Continue - можно продолжать отправку данных.

2xx - успешные. 200 OK - всё хорошо, 201 Created - ресурс создан.

3xx - перенаправления. 301 Moved Permanently - ресурс перемещён навсегда, 302 Found - временно перемещён, 304 Not Modified - ничего не изменилось.

4xx - ошибки клиента. 400 Bad Request - неверный запрос, 404 Not Found - страница не найдена.

5xx - ошибки сервера. 500 Internal Server Error - что-то сломалось на сервере.

7. Что такое REST и как ресурс в REST представлен на уровне URL?

REST - это архитектурный подход к созданию API, где всё строится вокруг ресурсов (любой объект данных: пользователь, товар, пост и т.д.).

На уровне URL ресурсы выглядят:

/users — список всех пользователей

/users/5 — конкретный пользователь с ID=5

/users/5/posts — все посты пользователя с ID=5

Каждый URL — это адрес уникального ресурса.

8. Какие типы данных поддерживает JSON? Приведите короткий пример JSON-объекта и массива.

JSON поддерживает:

-                   строки: "Привет";

-                   числа: 42, 3.14;

-                   логические значения: true или false;

-                   объекты: {"имя": "Анна", "возраст": 25};

-                   массивы: ["яблоко", "банан", "апельсин"];

-                   значение null — пустота.

9. В чём отличие вкладок Preview и Response в карточке запроса DevTools?

Response показывает сырые данные в том виде, в котором их отправил сервер. Это чистый текст без форматирования.

Preview браузер красиво оформляет эти же данные, чтобы их было удобно читать, объекты можно раскрывать и сворачивать, видна структура.

10. Какие заголовки чаще всего анализируются при оптимизации (например, Content-Type, Cache-Control, ETag, Authorization)?

Content-Type - формат данных (например, JSON, HTML, картинка).

Cache-Control - настройки кэширования.

ETag - проверка изменений данных.

Authorization - токен для авторизации.

Date - время отправки ответа.

Server - тип сервера (помогает в диагностике).

11. Какие приёмы снижения нагрузки на сеть можно использовать для API: пагинация, фильтрация, кэширование и др.?

В пагинации данные выдаются по частям, например, по 10 или 20 записей на одну страницу, это позволяет не загружать сразу все записи, если их тысячи или миллионы.

В фильтрации сервер возвращает только те данные, которые действительно нужны пользователю. Например, можно запросить посты только одного юзера через параметр ?userId=1.

В кэшировании часто используемые данные сохраняются на стороне клиента (в браузере) или на промежуточных серверах. При повторном запросе данные берутся из кэша, а не с основного сервера, что экономит трафик и ускоряет загрузку.

В уменьшении размера ответа вместо того, чтобы возвращать все поля объекта (например, полную информацию о пользователе со всеми полями), сервер может отдавать только самые нужные поля, исключая лишние.

С помощью правильных заголовков Cache-Control и ETag можно управлять кэшированием (например, указать, как долго хранить ответ, или проверять, изменились ли данные, прежде чем скачивать их заново).

С помощью сжатия данных сервер может сжимать ответ перед отправкой. Браузер или клиент получает сжатые данные и распаковывает их. Это сильно уменьшает объём трафика, особенно для текстовых данных вроде JSON или HTML.

12. Чем работа с API в Postman отличается от анализа запросов в DevTools, и когда уместен каждый инструмент?

DevTools хорош для анализа того, что реально происходит на странице в браузере. Можно увидеть все запросы, которые отправляет сайт, проверить время загрузки, кэширование и производительность. Используется, когда нужно понять, почему страница загружается медленно или что пошло не так.

Postman удобен для ручной работы с API, можно создавать любые запросы, менять заголовки и тело, сохранять запросы в коллекции, писать автотесты и работать с авторизацией. Используется, когда нужно протестировать API отдельно от сайта, отправить нестандартный запрос или автоматизировать проверки.
