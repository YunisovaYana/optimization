**Задание 2**

Создаем Router.php.  


```
<?php

namespace App\Core;

class Router
{
    private array $routes = [];

    public function get(string $path, callable|array $handler): void
    {
        $this->routes['GET'][$path] = $handler;
    }

    public function post(string $path, callable|array $handler): void
    {
        $this->routes['POST'][$path] = $handler;
    }

    public function dispatch(string $method, string $uri): void
    {
        $uri = parse_url($uri, PHP_URL_PATH);
        $uri = rtrim($uri, '/') ?: '/';

        foreach ($this->routes[$method] ?? [] as $route => $handler) {
            $pattern = '#^' . preg_replace('#\{(\w+)\}#', '(\d+)', $route) . '$#';

            if (preg_match($pattern, $uri, $matches)) {
                array_shift($matches);

                if (is_array($handler)) {
                    [$class, $action] = $handler;
                    (new $class())->$action(...$matches);
                } else {
                    $handler(...$matches);
                }
                return;
            }
        }

        http_response_code(404);
        echo '404 Not Found';
    }
}
```
Переписываем index.php (класс, как я рада)  

Теоретические вопросы:  


- Что изменилось?  
Код стал удобнее, убрался большой switch из index.php. Теперь index.php - это просто точка входа, он настраивает автозагрузку классов, создает объект роутера, регистрирует маршруты (говорит, какие адреса существуют) и передает управление роутеру. Сам процесс сопоставления адреса и действия переехал 🚴‍♀️ в отдельный класс Router.php.  

- Что делает роутер?  
Он берет текущий метод (GET или POST) и текущий URI (например, /article/5), заглядывает в свой внутренний список маршрутов ($routes) и ищет совпадение, если находит - он извлекает из маршрута функцию (или класс) и вызывает её, передавая туда нужные параметры (например, id = 5). Если не находит отдает ошибку 404. Он просто связывает URL с конкретным кодом.  

- Кто должен решать, что делать на /article/{id}?  
За это должен отвечать контроллер (или функция как сейчас в index.php), сам роутер просто видит совпадение паттерна. Вся бизнес-логика должна быть внутри обработчика, а не в роутере.  

- Что храниться в массиве $routes и что в нем храниться?
В массиве хранится карта маршрутов (таблица соответствий), многомерный массив:  
на первом уровне - HTTP-метод (GET, POST),  
на втором уровне - путь (URI) в виде строки (`/about`),  
В качестве значения хранится то, что нужно выполнить - в нашем случае это функция fn().

Теоретические вопросы:  
- Что делает контроллер?  
Контроллер - это посредник между пользователем и приложением. Он принимает запрос от пользователя, решает, какие данные нужно подготовить (например, получить список статей), и передает их дальше для отображения. Он управляет логикой работы конкретной страницы.  

- Как вы думаете, что мы с вами сделали не правильно ?  
Неправильно то, что осталась HTML-разметку (теги `<h1>`, `<p>`, `<a>`) прямо внутри контроллера и выводим её через echo. По правилам хорошей архитектуры (MVC) контроллер не должен заниматься версткой. Он должен только готовить данные, а за их отображение должны отвечать отдельные файлы.  

- Что не так с этим echo?  
Он смешивает логику (PHP-код контроллера) и представление (HTML-разметку) в одном файле (если потом понадобиться изменить верстку, придется лезть в PHP-класс контроллера, что неудобно). Если таких страниц станет много, контроллер превратится в огромную кучу echo с HTML, в которой невозможно будет разобраться.
