1. Собрать семантическое ядро по заданной тематике.

<h3>Этап 2. Проектирование структуры сайта</h3>  

На основе семантического ядра выделены семь кластеров. Кластер «Главная» объединяет общие запросы о фитнес-клубе, включая гендерные и локационные уточнения. Кластер «Тренажёрный зал» охватывает запросы о силовых тренировках и персональных занятиях. Кластер «Групповые занятия» включает йогу, пилатес, растяжку, единоборства и детский фитнес. Кластер «Блог» предназначен для информационных статей.

Структура URL спроектирована в соответствии с кластерами. Корневая страница соответствует кластеру «Главная». Разделы /gym/, /group/, /pool/, /membership/, /promo/ и /blog/ соответствуют остальным кластерам. Внутри блога выделены отдельные статьи по информационным запросам. <h3>Контрольные вопросы:</h3>  


1. Что такое семантическое ядро и зачем оно нужно?  
Семантическое ядро - упорядоченный набор поисковых запросов, по которым сайт должен находиться в выдаче. Характеристики запросов: частотность, конкуренция, интент (информационный, навигационный, транзакционный, коммерческий).  

2. Чем отличаются ВЧ, СЧ и НЧ запросы?  
Запросы различаются по частотности, то есть по количеству показов в месяц. Высокочастотные запросы имеют самые большие показатели и отличаются высокой конкуренцией. Среднечастотные запросы занимают промежуточное положение по количеству показов и уровню конкуренции. Низкочастотные запросы имеют небольшое число показов, но обычно легче продвигаются и лучше конвертируются за счёт узкой формулировки.  
   
3. Как кластеризовать запросы? Какие методы существуют?  
Кластеризация представляет собой группировку запросов по общему смыслу. Основной метод основан на совпадении топ-URL поисковой выдачи. Если по разным запросам в топе оказываются одни и те же страницы, такие запросы объединяют в один кластер. Второй метод основан на лемматическом анализе, при котором запросы группируются по совпадению ключевых лемм. Дополнительно применяется ручная кластеризация по интенту и тематике.  
 
4. Какие директивы используются в robots.txt ?  
Основные директивы включают User-agent, Allow, Disallow, Clean-param, Host и Sitemap. Директива User-agent определяет, к какому роботу относится правило. Allow разрешает обход раздела, Disallow запрещает. Clean-param указывает параметры, которые не влияют на содержимое страницы. Host задаёт основное зеркало сайта. Sitemap указывает путь к карте сайта.  
 
5. Для чего нужен Clean-param и как он работает в Яндексе?  
Clean-param сообщает роботу Яндекса, что определённые параметры в URL не влияют на содержимое страницы. Робот игнорирует эти параметры при обходе и не создаёт дублирующие страницы. Чаще всего директива применяется для UTM-меток и параметров сортировки. Это предотвращает склейку дублей и экономит краулинговый бюджет.  
 
6. Какие обязательные элементы есть в sitemap.xml?  
Обязательными элементами являются корневой тег urlset с указанием пространства имён и тег url для каждой страницы. Внутри тега url обязателен элемент loc с полным адресом страницы. Элементы lastmod, changefreq и priority являются необязательными, но рекомендуются для более точной передачи информации роботам.  
 
7. Как связаны кластеры СЯ и структура URL?  
Каждый кластер семантического ядра соответствует отдельному разделу сайта. Запросы одного кластера продвигаются одной страницей или группой страниц раздела. Такое соответствие обеспечивает релевантность страницы запросам и исключает каннибализацию, при которой несколько страниц конкурируют по одному запросу. Структура URL отражает иерархию кластеров.  
 
8. Какие теги <head> отвечают за SEO-оптимизацию страницы?  
К SEO-тегам относятся title, meta description, meta robots, link rel canonical и meta viewport. Тег title задаёт заголовок страницы и является одним из ключевых факторов ранжирования. Meta description формирует сниппет в выдаче. Meta robots управляет индексацией. Canonical указывает канонический адрес страницы. Viewport обеспечивает корректное отображение на мобильных устройствах.  
 
9. Что такое rel="canonical" и когда его применяют?  
Атрибут rel canonical указывает поисковым системам канонический адрес страницы. Он применяется при наличии дублирующегося или похожего контента на разных URL. Например, при наличии параметров сортировки, при доступе к странице по разным протоколам или при копировании контента. Canonical помогает объединить сигналы ранжирования на одной странице.  
 
10. Как проверить корректность robots.txt и sitemap.xml?
Проверка robots.txt выполняется через раздел «Инструменты для вебмастера» в Яндекс.Вебмастере и через Google Search Console. Сервисы показывают, какие директивы распознаны и какие страницы закрыты от обхода. Проверка sitemap.xml выполняется через валидаторы XML и через инструменты вебмастера. Дополнительно можно открыть файл в браузере и убедиться в отсутствии ошибок структуры и в доступности указанных URL.
