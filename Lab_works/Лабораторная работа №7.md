2.0. Подготовительный этап
В качестве исходного сайта использовался проект my-site, созданный в лабораторной работе 3 и размещённый на GitHub Pages. Сайт содержит несколько страниц, включая главную, страницу услуг и страницу контактов.

2.1. Подключение Google Analytics 4
Для подключения GA4 я перешёл на сайт analytics.google.com и авторизовался под своей учётной записью. В разделе администратора создал новый аккаунт и веб-ресурс. При создании ресурса указал адрес сайта на GitHub Pages и присвоил ему название. После создания ресурса GA4 предоставил идентификатор потока данных и скрипт gtag.js. Этот скрипт был скопирован и вставлен в секцию head всех страниц сайта my-site. После размещения обновлённых страниц на GitHub Pages я убедился, что скрипт загружается корректно. Для проверки использовал встроенный отладчик GA4, который подтвердил поступление данных о посещениях.

2.2. Подключение Яндекс.Метрики
Для подключения Метрики я перешёл на metrika.yandex.ru и создал новый счётчик. В настройках счётчика указал домен сайта на GitHub Pages и дал счётчику понятное название. После создания счётчика Метрика предоставила код вставки, который я разместил в секции head всех страниц сайта. После публикации обновлённых страниц я проверил работоспособность счётчика через встроенный валидатор Метрики, который подтвердил корректный приём данных.

2.3. Настройка цели
В обеих системах аналитики была настроена цель типа Destination Goal, то есть цель по посещению определённой страницы. В качестве целевой страницы выбрана страница contacts.html. В GA4 цель настроена через раздел событий и преобразований, где в качестве условия указано событие page_view с параметром page_location, содержащим contacts.html. В Яндекс.Метрике цель создана через раздел целей с типом «Посещение страницы» и условием, что URL содержит contacts.html. Такая настройка позволяет фиксировать переходы пользователей на страницу контактов как достижение цели в обеих системах.

2.4. Имитация трафика
Для генерации данных я открыл сайт в браузере и последовательно переходил между страницами. С главной страницы переходил на страницу услуг, затем возвращался на главную, открывал страницу контактов, что имитировало достижение цели. Дополнительно открывал сайт в режиме инкогнито и с другого браузера, чтобы создать несколько сессий. Переходы выполнялись несколько раз в течение нескольких дней, чтобы накопить статистику. Также имитировал переходы с внешних источников, вставляя ссылки на сайт в социальные сети и мессенджеры, что позволило получить данные о различных источниках трафика.

2.5. Анализ данных
После накопления статистики я перешёл к анализу отчётов в обеих системах.

В Google Analytics 4 в разделе отчётов о жизненном цикле я проверил количество сессий. Отчёт показал несколько сессий, соответствующих выполненным переходам. В отчёте об источниках трафика отображались прямые заходы и переходы с внешних ресурсов. В отчёте о страницах и экранах наиболее просматриваемыми оказались главная страница и страница услуг. В разделе преобразований отображались достигнутые цели по посещению contacts.html.

В Яндекс.Метрике в сводном отчёте я проверил количество визитов и просмотров. Отчёт по источникам трафика показал распределение между прямыми заходами и переходами с внешних сайтов. Отчёт по популярным страницам выявил наиболее посещаемые страницы. В разделе конверсий отображались достижения цели по посещению страницы контактов.

Скриншоты отчётов обеих систем были сохранены для приложения к отчёту.

2.6. Сравнение GA4 и Яндекс.Метрики
Интерфейс GA4 сложнее и требует времени на освоение, но предоставляет большую гибкость в настройке отчётов. Интерфейс Яндекс.Метрики проще и интуитивнее, что ускоряет начало работы. Интеграция с рекламой в GA4 выполнена через Google Ads, в Метрике через Яндекс.Директ. Доступность GA4 не вызывает вопросов, тогда как доступ к Метрике может быть ограничен в зависимости от региона. Обе системы успешно справились с задачей сбора и анализа данных, однако для базового анализа достаточно возможностей Метрики, а для глубокой аналитики с гибкими отчётами предпочтительнее GA4.

3. Ответы на контрольные вопросы
Веб-аналитика представляет собой процесс сбора, измерения, анализа и интерпретации данных о поведении посетителей сайта с целью оптимизации его работы и повышения эффективности маркетинга.

Сессия представляет собой последовательность действий пользователя на сайте в рамках одного визита. Сессия начинается при первом взаимодействии пользователя с сайтом и завершается после периода неактивности, обычно составляющего 30 минут.

Посетитель представляет собой уникального пользователя, который зашёл на сайт хотя бы один раз. Просмотр представляет собой факт загрузки одной страницы сайта. Один посетитель может совершить множество просмотров в рамках одной или нескольких сессий.

Показатель отказов представляет собой процент сессий, в рамках которых пользователь просмотрел только одну страницу и не совершил никаких действий. Высокий показатель отказов может указывать на несоответствие содержимого страницы ожиданиям пользователя или на проблемы с удобством сайта.

Отслеживать можно различные цели, включая посещение определённой страницы, скачивание файла, заполнение формы, регистрацию, оформление заказа, клик по кнопке или ссылке, просмотр видео и другие действия, которые считаются полезными для бизнеса.

Аналитика помогает в улучшении сайта путём выявления проблемных страниц с высоким показателем отказов, определения популярных разделов, понимания источников трафика и поведения пользователей. На основе этих данных можно оптимизировать структуру сайта, улучшать контент, настраивать навигацию и повышать конверсию.

Конверсия представляет собой целевое действие пользователя на сайте, которое приносит пользу бизнесу. Это может быть покупка, регистрация, заполнение формы, подписка или переход на определённую страницу. Конверсия измеряется как отношение числа целевых действий к общему числу посетителей или сессий.

Отслеживание источников трафика важно потому, что позволяет понять, откуда приходят пользователи, какие каналы маркетинга работают эффективно, а какие требуют оптимизации. Это помогает распределять бюджет на рекламу и улучшать стратегию продвижения.

Узнать, что пользователь кликнул по элементу, можно с помощью настройки событий в системах аналитики. Для этого на элемент добавляется обработчик события клика, который отправляет данные в аналитическую систему. В GA4 это делается через gtag с событием click, в Метрике через метод reachGoal или через настройку событий в интерфейсе.

GA4 отличается от Universal Analytics рядом принципиальных моментов. GA4 использует событийную модель данных вместо сессионной, что позволяет отслеживать любые взаимодействия как события. GA4 работает на основе машинного обучения для прогнозирования поведения пользователей. GA4 поддерживает кросс-платформенное отслеживание, объединяя данные с сайтов и приложений. GA4 не использует семплирование данных в той же мере, что UA. Universal Analytics прекратил обработку данных в 2023 году, и GA4 является его преемником с принципиально новой архитектурой.
